# P11 Closeout - 2026-07-12

P11 is closed as the JAX runtime/benchmark/solver-policy stabilization phase.
The active runtime is cleaner and more explicit:

- benchmark instrumentation and curve campaigns were rebuilt around reproducible
  local, GPU, and Kaggle runs;
- CPU double-cable production policy is Thomas-only;
- single-cable stays on the JAX tridiagonal route;
- GPU double-cable keeps typed explicit routes, with tiled Thomas/Triton kept as
  a strong large-population candidate, not a default policy;
- public solver selection lives under `ExecutionPolicy.solvers`;
- `BatchOptions` controls recording/chunking only;
- inspection now reports one structured solver route contract for both cable
  families through `CableSolverRoute`.

## Closed Decisions

- Do not implement the NumPy runtime as the next step. Keep it as a future
  reference/bonus runtime.
- Do not keep CPU PCR, PCR-SoA, tiled-Thomas, or Triton double-cable routes as
  production choices.
- Do not add membrane-model-specific runtime/solver branches. MRG remains a
  realistic benchmark workload, not a runtime special case.
- Do not make Triton/tiled Thomas the GPU default inside P11. Promotion needs a
  smaller explicit policy rule plus fresh validation.
- Do not tune solver variants from HLO size alone. Keep only changes that win on
  realistic or real-stage benchmark evidence.

## Deferred Backlog

These tasks were deliberately moved out of P11. They are not blockers for the
P11 closeout, but they should remain visible for future runtime/benchmark work.

- [ ] Define the GPU double-cable default policy threshold for
  tiled-Thomas/Triton versus PCR-SoA. Start from the P11C-F policy matrix, then
  run a smaller repeat/check campaign before changing `auto`.
- [ ] Validate Triton/tiled Thomas as a preferred selectable GPU route for
  supported fp32 large-population double-cable shapes, including dependency
  failure behavior, cold/warm cache state, memory, and physical curve
  correctness.
- [ ] Continue unifying non-solver extracellular input lowering across
  single-cable and double-cable paths. In particular, define a
  preparation-level shared-waveform/scaled-waveform contract so threshold-style
  workloads do not repeatedly prove temporal equivalence row by row.
- [ ] Decide time-chunk defaults from a policy-specific follow-up, not from P11:
  compare adaptive candidates across threshold/recruitment, full Vm, probe Vm,
  observer-only, CPU/GPU, memory, and correctness.
- [ ] Keep recruitment amplitude micro-batching as a later high-level workflow
  optimization. Test `amplitude_batch_size` values only after low-level
  observer/input bottlenecks are stable.
- [ ] Carry over backend-neutral model/compiler optimizer cleanup under
  benchmark control: common subexpression elimination, unused diagnostic
  pruning, stable optimized-graph hashing, and explainable before/after
  summaries.
- [ ] Carry over JAX-specific generated fusion cleanup under benchmark control:
  requested-observable pruning, generated conductance/state update fusion,
  avoiding unrequested intermediate transport, and direct solver-kernel fusion
  beyond the current P7 class subset.
- [ ] Remove or reject dense internal fallback paths only after compact or
  factorized equivalents have equivalence tests and realistic benchmark
  evidence.
- [ ] Explore GPU dispatch scheduling later: memory-aware bucket/coalescing
  first, optional async enqueue second.
- [ ] Validate any double-cable rank-K compact `Vext` path only after dense
  equivalence and benchmark evidence.
- [ ] Keep future GPU solver work grounded in the P11 idea-document critical
  reviews. New candidates need small correctness gates, then realistic
  benchmarks before promotion.
- [ ] Re-run NRV validation only for numerical behavior changes, and pair any
  performance claim with fresh hotpath or realistic benchmark artifacts.
